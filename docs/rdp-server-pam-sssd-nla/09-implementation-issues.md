The integrated `server/frdp/frdpd` target builds successfully and now includes the partial configuration
parser. The helper prototype sources in `server/frdp/frdp-authd`, `server/frdp/frdp-sesmand`,
`server/frdp/frdp-session-agent`, `server/frdp/frdp-krb-authd`, and `tools/frdpctl` now have CMake targets

Package build verification is still partial, but both preview package formats now have local smoke evidence:
the root `debian/` metadata supports a verified server-only `dpkg-buildpackage` binary build, and
`packaging/rpm/frdpd.spec` supports a verified server-only `rpmbuild -bb --nodeps` binary build when

signing and reproducible-build notes now define the release build contract, while dependency-checked RPM
distro CI and full distro policy validation remain open.

## Implemented since the previous issue pass

- The root-level `/frdpd` implementation is no longer present, so the earlier divergence/TLS-only/blocking-accept issues for that path are retired.
- `frdp-authd` now checks `mmap()` failure with `MAP_FAILED`; the remaining locked-memory concern is tracked in FRDP-016.
- `frdp-authd` no longer calls `initgroups()` in the broker process.
- `frdpd` now accepts `--config` and applies implemented `frdpd.toml` server/auth fields before CLI overrides, including enforced `ntlm_fallback = false`; unsupported Kerberos identity policy fields are rejected instead of being silently accepted.
- `frdp-config` now uses bounded string copies and strict integer/boolean parsing for fields it understands.
- `frdp-authd` IPC now rejects overlong/non-terminated auth fields, unsafe socket paths, and peers with a different effective UID on Linux; its socket is created with `0600` permissions.
- `frdp-sesmand` now includes `<grp.h>` and passes a strict syntax-only check.
- The standalone `frdp-sesmand` prototype now keeps the PAM handle for the session lifetime, applies a bounded supplementary group list in the child after `fork()`, and records a process group for cleanup.
- The standalone `frdp-session-agent` now fails fast when `Xvfb` exec fails instead of entering an infinite sleep loop.
- `server/frdp` now builds and installs `frdp-authd`, `frdp-sesmand`, `frdp-session-agent`, and `frdpctl`; `frdp-authd --config <path>` and `frdp-sesmand --config <path>` both read implemented policy from `frdpd.toml`, installed helper units use that shared config, `frdpctl status` / `list-sessions` / `kill-session` can use `frdp-sesmand` session IPC, and `frdpctl reload` now sends a session-manager IPC request that makes `frdp-sesmand` reread `[auth].pam_service` plus supported `[session]` resource guards for future sessions with an explicit applied-policy response. The session-manager config load/reload path fails closed on active Kerberos or clipboard runtime policy while those handlers are unsupported. Full runtime reload for listener sockets, TLS material, channel policy, clipboard policy, and helper topology remains unimplemented. It also builds `frdpd-ipc-demo`, builds but does not install the `frdp-krb-authd` prototype when GSSAPI is available, and installs `frdpd.toml`.
- `server/frdp` now installs a dedicated non-interactive PAM service example at `/etc/pam.d/frdpd` through the CMake `server` component.
- `server/frdp` now installs `frdpd`, `frdp-authd`, and `frdp-sesmand` systemd service examples with baseline sandboxing directives, including clock and hostname protection, plus inactive SELinux/AppArmor draft policy examples through the CMake `server` component; `TestFreeRDPFrdpSystemd` verifies the units and checks their expected hardening directives when `systemd-analyze` is available, the SELinux draft is compiled/packaged by CTest when `checkmodule` and `semodule_package` are available, and the AppArmor draft is parser-validated by CTest when `apparmor_parser` is available.
- Integrated `frdpd` now calls `pam_setcred(PAM_ESTABLISH_CRED)` after successful auth/account checks and `pam_setcred(PAM_DELETE_CRED)` during cleanup.
- Integrated `frdpd`, `frdp-authd`, and `frdp-sesmand` fail closed if core dumps/non-dumpable process hardening cannot be applied before handling credentials or sessions.
- `frdp-authd` no longer accepts passwords through positional command-line arguments; it only exposes the local `--socket` IPC server mode.
- `frdp-sesmand` no longer creates a hard-coded `nobody` session on startup; the standalone helper requires an explicit `--open-session <user>` request and `FRDP_SESMAND_ALLOW_STANDALONE=1` development opt-in.
- `frdpd` now requires `frdp-authd` and `frdp-sesmand` sockets for normal startup; the old direct peer-worker PAM fallback build option and CLI path have been removed.
- `frdpd` can now route password-backed auth/account checks through `frdp-authd` over IPC when `auth_socket` or `--auth-socket=<absolute-path>` is configured.
- `frdp-authd` IPC requests now carry the remote host in addition to the normalized user and password; PAM service selection remains broker-side, `frdp-authd --config <path>` reads `[auth].pam_service`, and `--pam-service` remains the direct standalone override.
- Integrated `frdpd` now generates a per-peer correlation id, includes it on accept/auth/logon/activate/disconnect logs, and sends it in `frdp-authd` IPC auth requests; `frdp-authd` uses a valid incoming id for syslog audit events and falls back to a local UUID when the request omits or sends an invalid id.
- Auth broker IPC request and response payloads now use explicit little-endian/fixed-field wire encoding with exact payload-size checks; password-bearing request wire buffers and authorization-token-bearing response wire buffers are cleared after use.
- `frdp-sesmand` now exposes a guarded local `--socket` IPC server; integrated `frdpd` can open and close managed sessions through configured `session_socket` / `--session-socket=<absolute-path>` after authentication and static-channel policy checks pass.
- The canonical `FRDP_IPC_SESSION_REQUEST_V3` session-open handoff and shared `FRDP_IPC_SESSION_RESPONSE` now use explicit little-endian/fixed-field wire encoding with exact payload-size checks; authorization-bearing V3 request wire buffers are cleared after use.
- `FRDP_IPC_SESSION_CLOSE_REQUEST` and `FRDP_IPC_SESSION_DISCONNECT_REQUEST` now use explicit little-endian/fixed-field wire encoding for `frdpd`, `frdpctl`, and `frdp-sesmand` close/detach paths.
- `FRDP_IPC_SESSION_LIST_RESPONSE` and `FRDP_IPC_SESSION_RELOAD_RESPONSE` now use explicit little-endian/fixed-field wire encoding with exact payload-size checks; their request messages remain header-only.
- Per-session agent input, frame metadata, and resize IPC messages now use explicit little-endian/fixed-field wire encoding with exact metadata payload-size checks; frame pixels remain a bounded raw byte tail after `FRDP_IPC_AGENT_FRAME_RESPONSE` metadata.
- Shared FRDP IPC clients now set send/receive timeouts, use `MSG_NOSIGNAL` when available so disconnected IPC peers return errors instead of terminating the process with `SIGPIPE`, and encode/decode the common IPC header as fixed little-endian `type`/`payload_len` fields.
- Session IPC now passes session ids and correlation ids into `frdp-session-agent`, which includes them in startup and display-backend exit logs.
- `frdp-session-agent` now reports readiness only after Xvfb `exec()`, X display open, and XTest checks pass, and `frdp-sesmand` fails session creation if agent readiness is not reported.
- Session IPC now creates a root-owned per-session agent control socket, returns the path to `frdpd`, forwards keyboard/mouse/Unicode/synchronize input events to `frdp-session-agent`, and has the agent validate root peer credentials plus session ids before injecting scancode keyboard, Unicode BMP text, and mouse events into Xvfb through XTest/X11.
- `frdpd` now pulls bounded raw framebuffer tiles from the session agent over the same root-only control socket, the agent uses XDamage-backed dirty-tile state to return selected dirty tiles or clean-tile responses when available, `frdpd` suppresses unchanged tiles with per-peer hashes, and changed tiles are sent to the RDP client as raw FreeRDP bitmap updates or negotiated minimum-color-loss/no-subsampling NSCodec `SurfaceBits` when the encoded tile is smaller.
- `frdp-sesmand` session IPC now performs POSIX account/group lookup, verifies the bounded group payload from the signed handoff, applies it with `setgroups()` before uid/gid drop, owns the PAM session, and cleans up agent process groups on close requests.
- `frdpd` now enables RDP dynamic resolution/display-control settings, handles monitor-layout changes, asks the session agent to resize the Xvfb display through XRandR, and updates peer geometry only after the agent confirms the backend resize.
- `frdpd` now uses a bounded raw-tile output scheduler with a shorter active-peer wait interval, a two-tile pump cap, a pump time check, and a reduced frame IPC timeout to improve initial/full-refresh and dirty backlog progress while keeping the slow-agent timeout budget comparable to the prior single-tile path.
- `frdpd` now enforces configured `max_connections` before authentication, channel checks, or managed-session creation; it can be set from `frdpd.toml` or overridden with `--max-connections=<n>`.
- `frdpd` now applies configurable static virtual-channel filtering during client capability processing; `[channels].static_mode` supports blocklist/allowlist semantics, defaults to empty blocklist mode, uses exact `static_deny` / `static_allow` lists, validates raw `CHANNEL_DEF` names fail-closed, rejects `cliprdr` at the runtime channel gate while clipboard is disabled, rejects unimplemented static channels plus `rdpsnd`/`rdpdr` at the runtime channel gate while audio output and device redirection are unsupported, and keeps `drdynvc` guard-denied until DVC transport and handlers are explicitly enabled. `[channels].dynamic_mode` plus `dynamic_deny` / `dynamic_allow` is parsed as exact-name policy for the DVC authorization callback. `[clipboard]` now parses disabled-by-default text clipboard policy with explicit direction and bounded maximum text payload, and `frdpd` rejects active text mode until runtime handling is enabled. The server-side WTS API now has a DVC authorization hook before dynamic-channel `CREATE_REQUEST` emission, and `frdpd` opens/checks/closes a WTS virtual-channel manager without auto-opening `drdynvc`, with that callback installed. Focused CTest coverage exercises config parsing, clipboard policy validation, feature-aware `cliprdr`/`rdpsnd`/`rdpdr`/arbitrary static denial, `CHANNEL_DEF` validation, and the WTS runtime DVC authorization deny path. Useful channel handlers are still not implemented.
- `frdpd`, `frdp-authd`, `frdp-sesmand`, `frdp-session-agent`, and `frdpctl` now escape client/IPC/CLI/environment-supplied output fields before writing peer, auth, channel, session, helper lifecycle, or admin CLI events; password payloads remain unlogged.
- `frdpctl` now escapes IPC-supplied session ids, users, display names, session-manager errors, and session-manager socket paths before writing them to the admin terminal.
- Shared FRDP IPC client sockets and `frdp-authd` / `frdp-sesmand` listener plus accepted IPC client sockets are now created close-on-exec where supported, with `fcntl(FD_CLOEXEC)` fallback; the `frdp-sesmand` per-session agent control socket remains intentionally inheritable for `frdp-session-agent` startup.
- `frdp-authd`, `frdp-sesmand`, and per-session agent control listener startup now refuse to unlink an existing live Unix socket path; stale same-owner socket nodes are removed only after a nonblocking live-listener probe and same-inode recheck.
- `frdp-authd` and `frdp-sesmand` reject oversized inbound IPC request payload lengths before type-specific request handling while keeping their service loops alive.
- Managed session opens now use `FRDP_IPC_SESSION_REQUEST_V3` with a short-lived HMAC auth token issued by `frdp-authd` after successful authentication. The token payload is length-prefixed and covers the authenticated user, remote host, correlation id, POSIX uid/gid, bounded supplementary groups, account-present state, nonce, and expiry; `frdp-sesmand` verifies those fields, consumes accepted nonces once, rejects mismatched POSIX group payloads, and rejects legacy V1/V2 session-open requests before body decode.
- `frdp-sesmand` display allocation skips display numbers already present in its session registry or visible through local X lock/socket paths, and selected displays are held with FRDP-owned atomic reservation files for the session lifetime. Linux reservations now store a versioned owner PID plus `/proc` start time, reconcile both disappeared owners and PID reuse, retain fail-closed legacy PID-only parsing, and use same-inode checks before unlink; the broader session registry is still not durable or restart-reconnectable.
- `frdp-sesmand` now has small in-memory helpers for session state transitions, cleanup decisions and reconnect selection, records the hard-close cleanup path through `ACTIVE` -> `STOPPING` -> `DEAD`, accepts normal peer disconnect as a detach request that marks an active in-memory session `DISCONNECTED`, and requires a valid V3 authorization before explicit session-id reconnect requests can attach to that disconnected entry instead of silently treating them as fresh-session opens; durable state plus restart reconciliation remain unimplemented.
- `frdp-sesmand` now handles SIGINT/SIGTERM by stopping the IPC accept loop and cleaning up tracked agent process groups, PAM sessions, and runtime sockets before exit.
- `frdpd`, `frdp-authd`, `frdp-sesmand`, and `frdp-session-agent` install explicit non-restarting SIGINT/SIGTERM handlers so stop requests are observed by their main loops and fail closed if handler installation fails; `frdp-authd` also closes and unlinks its IPC socket on graceful stop, and a running `frdp-session-agent` terminates its display backend on stop.
- Focused CTest coverage now starts live `frdp-authd` and `frdp-sesmand` helpers together, runs default-build `frdpd` with both live helper sockets, verifies startup reaches the certificate/key gate instead of the helper-topology gate, and then proves both helper service loops remain responsive.
- Integrated `frdpd` now zero-frees the peer-owned FreeRDP auth identity immediately after `frdpd_authenticate_identity()` returns and the brokered result has been copied into `frdpd` session context.
